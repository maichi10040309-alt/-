# 販売管理ソフト

見積書・納品書・請求書・領収証の作成から、得意先/商品台帳の管理、締め処理(合計請求書の一括発行)、売掛金管理、売上集計・分析まで行える販売管理ソフトです。「販売らくだ」を参考に、そこで使える主要機能を一通り実装しています。

店内の1台をサーバーにして、同じ店内の他のパソコンからも同時にアクセスできます(後述)。

## 主な機能

- **伝票作成**: 見積書・納品書・請求書・合計請求書・領収証をそれぞれ作成・印刷(PDF出力はブラウザの印刷機能を利用)
- **伝票の変換**: 見積書→納品書→請求書→領収証への変換で二重入力を防止
- **得意先台帳**: 得意先の登録・編集、単価ランク・得意先別掛率・締め日/支払日の設定、CSVインポート/エクスポート
- **商品台帳**: 商品の登録・編集、複数単価(単価1〜3)・仕入原価の設定、CSVインポート/エクスポート
- **締め処理**: 対象期間・得意先を指定して未請求の納品書をまとめて合計請求書を一括発行
- **売掛金一覧**: 得意先ごとの請求額・入金額・売掛残高を集計表示
- **売上集計・分析**: 得意先別・商品別・月別の売上集計とグラフ表示
- **インボイス制度対応**: 適格請求書発行事業者登録番号の印字、税率(10%/8%/非課税)ごとの税額表示
- **複数台のパソコンで共有**: 店内LAN経由で複数のパソコンから同じデータを同時に利用可能(リアルタイム反映)
- **設定**: 自社情報・税設定(端数処理)、データのバックアップ/復元(JSON)

## しくみ

1台のパソコン(以下「サーバー用パソコン」)の中で、小さなプログラム(サーバー)がデータを持っています。他のパソコンはブラウザでそのサーバーにアクセスして使います。同じ店内(同じWi-Fi/LAN)にあるパソコンなら、インターネット接続は不要です。

```
[サーバー用パソコン] ← ブラウザで http://localhost:4000/
        ↑
        │ 同じLAN内
        ↓
[他のパソコンA] [他のパソコンB] ← ブラウザで http://<サーバー用パソコンのIP>:4000/
```

## 1台だけで使う場合

### 1. 準備するもの

- [Node.js](https://nodejs.org/)(18以上推奨)がインストールされていること
- このリポジトリを取得済みであること(`git clone` または ZIP ダウンロード)

### 2. 起動方法(かんたん)

このフォルダの中にある起動ファイルをダブルクリックするだけで、初回は必要なファイルのインストールまで自動で行い、ブラウザが自動で開きます。

- Windows: `start-windows.bat`
- Mac: `start-mac.command`
  - 初回のみ「開発元を確認できません」等の警告が出る場合、右クリック→「開く」を選んでください。

起動したウィンドウ(黒い画面)は、使っている間は閉じずにそのままにしておいてください。閉じる、または `Ctrl+C` を押すとソフトが終了します。次に使うときも同じファイルをダブルクリックするだけです。

### 3. 起動方法(コマンドで実行する場合)

```bash
npm install   # 初回のみ
npm run start
```

表示された `http://localhost:4000/` をブラウザで開きます。

## 複数台のパソコンで使う場合(店舗内LAN共有)

### 1. サーバー用パソコンを1台決める

営業時間中ずっと電源が入っている、店内で一番使われるパソコン(レジ横のPCなど)がおすすめです。そのパソコンで上記の「起動方法」を実行してください。

### 2. 起動時に表示されるURLを確認する

起動すると、黒い画面(ターミナル)に次のように表示されます。

```
=== 販売管理ソフト サーバー起動 ===
このパソコンで開く:   http://localhost:4000/
他のパソコンから開く: http://192.168.1.23:4000/
```

`他のパソコンから開く` に表示されたURL(数字の部分は環境によって異なります)を覚えておいてください。

### 3. 他のパソコンから接続する

他のパソコンでは `npm install` やソフトのインストールは不要です。ブラウザ(Chrome、Edge、Safariなど)を開き、手順2で確認したURL(例: `http://192.168.1.23:4000/`)をアドレスバーに入力するだけで、同じデータにアクセスできます。ブックマークしておくと便利です。

### 4. 注意点

- サーバー用パソコンの電源が切れている間、他のパソコンからは使えません。
- 初回接続時、Windowsのファイアウォールで「Node.js の通信を許可しますか?」のような確認が出ることがあります。「プライベートネットワーク」へのアクセスを許可してください。
- 複数人が同時に伝票を作成しても番号が重複しないようになっています。ただし同じ伝票を複数人が同時に編集した場合は、後から保存した内容が優先されます。
- Wi-Fiのゲスト用ネットワークなど、パソコン同士が通信できないネットワークでは接続できません。同じLAN(同じルーター配下)に接続してください。

## データの保存・バックアップについて

データはサーバー用パソコンの `server/data/db.json` というファイルに保存されます。定期的に「設定」画面の「バックアップを保存」でJSONファイルを書き出し、USBメモリやクラウドストレージなど別の場所にも保管しておくことをおすすめします(パソコンの故障に備えて)。復元も同じ画面から行えます。

さらに、`server/data/db.json` とは別に `server/data/backups/` フォルダへ**1日1回、その日の状態が自動的にバックアップ**されます(直近30日分を保持)。何らかの理由でメインの `db.json` が見つからない・壊れている状態でサーバーを起動した場合は、このバックアップフォルダから自動的に最新の状態を復元します(その旨がサーバーの起動ログに表示されます)。ただし、これはあくまで保険であり、正しいフォルダでサーバーを起動しているかの確認や、上記の「バックアップを保存」による外部保管に代わるものではありません。

**`git pull` について**: `server/data/` フォルダ(db.jsonおよびbackupsフォルダ)はGitの管理対象外(.gitignore)になっているため、`git pull` を実行してもこのフォルダの中身が変更・削除されることはありません。もし `git pull` の直後にデータが消えたように見える場合は、以下をご確認ください。

- サーバーをいつも起動しているのと**同じフォルダ**で `git pull` を実行したか(誤って別の場所に新しくフォルダを用意していないか)
- `server/data/db.json` のファイルが本当に存在するか、サイズが小さくなっていないか(数KB程度であれば空のデータベースが新規作成された状態です)
- `git pull` 以外に `git clean` や「変更を破棄」等の操作を行っていないか(Gitクライアントによっては、この操作でGit管理外のファイルも削除される場合があります)

## アップデート方法

コードを更新した場合は、サーバー用パソコンで起動前に一度だけ次を実行してください。

```bash
git pull
npm install
```

## 開発用コマンド

```bash
npm run dev      # フロントエンドの開発サーバー(HMR対応、要:別ターミナルで npm run server)
npm run server   # バックエンド(API)のみ起動
npm run build    # 本番用ビルド(distフォルダに出力)
npm run start    # ビルド後、バックエンドがdistを配信する形で起動(通常利用時はこちら)
```
